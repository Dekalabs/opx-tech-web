01 · El modelo

Todos los proyectos parten de la misma estructura.

En cada proyecto cambian los datos, la marca y los textos. La organización de los ficheros y la forma de trabajar se mantienen.

Datos canónicos

Un único JSON fija nombres, tiempos y estados. La web y el vídeo incorporan esos datos, y las capturas se comprueban contra ellos.

Web con presentación

Una landing narrativa que, con una tecla, se convierte en la presentación de la reunión. La misma web sirve para navegar y para exponer.

Escena 3D (opcional)

Cuando ver el proceso ayuda a entender el producto, la escena reproduce el caso real. No se utiliza como decoración.

Capturas de producto

Pantallas reales del producto con el caso canónico cargado. Cuando cambia la interfaz, un comando vuelve a generarlas.

Vídeo locutado

Un manifiesto define el guion, los tiempos y la voz. Para actualizar el vídeo, se modifica ese fichero y se vuelve a renderizar.

Verificación y despliegue

La landing y el vídeo incluyen sus propias comprobaciones. finish.sh audita la web y prepara solo los ficheros publicables.

# Web and audiovisual production with AI

This project produces the white-label web-and-media package for
[[PRODUCT_NAME]] under [[PROJECT_ROOT]]. The landing, presentation,
captures, optional 3D scene, optional video and deployment package must
describe the same approved product and canonical case.

## Scope

- Work inside [[PROJECT_ROOT]] unless the task explicitly expands scope.
- Preserve valid existing work and make the smallest coherent change.
- Do not add rules outside this web-and-media package.

## Source order

Read and resolve conflicts in this order:
1. Applicable parent repository instructions.
2. This AGENTS.md and the project README.
3. Product sources: [[PRODUCT_SOURCES]].
4. Brand sources and client configuration: [[BRAND_SOURCES]].
5. Approved copy in COPY.md.
6. Canonical case in data/[[CANONICAL_CASE_FILE]].
7. Existing target source files.
8. [[REFERENCE_PROJECT_ROOT_OR_NONE]] for architecture and quality only;
   never use it as product truth, copy, brand or feature evidence.

## Project map

- COPY.md — approved narrative, terminology, claims and CTAs.
- .gitignore — repository-specific secret, cache and generated-output boundary.
- data/ — canonical JSON, schema notes and dependency-free validation.
- landing/ — responsive web, presentation mode, local bundles and audit.
- capture/ — reproducible product capture tools and manifests.
- captures/ — generated originals; do not edit them by hand.
- video/ — optional manifest-driven Remotion/TTS workflow and licences.
- deploy/dist/ — generated publishable files only.
- wrangler.jsonc — versioned configuration for the isolated development Worker.
- finish.sh — final audit and deployment-package preparation.

## Working rules

- Keep one canonical JSON; generated copies are read-only.
- Write natural es-ES using approved product and client terminology.
- Do not invent claims, metrics, integrations, states or workflows.
- Use local assets and bundles; no CDN or unexpected runtime request.
- Keep unfinished 3D, video or new sections behind a named flag set to false.
- Regenerate captures, bundles and renders with documented commands;
  never retouch generated evidence manually.
- Add a nested AGENTS.md only for genuine directory-specific differences.
- Keep main connected only to the protected development Worker; production is a
  separate, explicitly authorized promotion.

## Verification

- Run `node data/validate.mjs` when canonical data changes.
- From `landing/`, run `npm run build` and `npm run check` after web changes.
- Verify requested viewport, state and deterministic time with screenshots.
- Follow capture/*/README.md and video/README.md when those components exist.
- Run `./finish.sh` only when preparing the publishable package.
- Before Git operations, inspect `git status --short`; verify ignored paths with
  `git check-ignore -v` and run the approved secret scanner.
- Report commands, exit codes, evidence paths and a done/not-done verdict.

## Code Review Rules

- Request an independent review when a feature closes or after three verified
  rounds, whichever happens first; always review before merge or publication.
- The reviewer starts from the acceptance criteria, sources, diff and evidence
  in a fresh context. The producing agent's summary is context, not proof.
- For high-impact work, review product/content, design/UX/accessibility and
  engineering/QA in parallel, then merge findings into one evidence-led list.
- The producing agent fixes blockers; an independent reviewer verifies them.

## Permissions

- Never expose or request secrets when an authenticated local session suffices.
- Do not commit, push, publish, deploy, buy assets or use paid services unless
  the current request explicitly authorizes that exact action.

12 · La escena 3D, cuándo y cómo

Añade una escena 3D solo si ayuda a entender el producto.

  • Cuándo usarla: la escena se justifica cuando ver el proceso en el espacio explica más que contarlo. Si no aporta claridad, se omite.
  • Nada decorativo: cada objeto o efecto representa un paso real; humo y agua solo aparecen cuando pertenecen al caso.
  • Ritmo y anclas: la animación sigue los datos canónicos, y los rótulos HTML se proyectan sobre puntos 3D.
  • Encuadre calculado: la escena ocupa una fracción fija de la pantalla en cualquier tamaño; el recorte y la niebla escalan con la cámara.
  • Comportamiento alternativo: sin WebGL se oculta sin mostrar errores; con renderizado por software reduce la resolución y la frecuencia; con prefers-reduced-motion muestra un fotograma fijo.

15 · Recomendaciones prácticas

Seis prácticas que evitan errores frecuentes.

Define dónde vive cada dato

La información de producto, marca y contenido debe mantenerse en un único archivo o directorio. Genera las copias necesarias y no las edites a mano.

Acota cada encargo a la IA

Indica el resultado esperado, los archivos que puede modificar y la prueba de aceptación. Divide los cambios grandes en rondas que puedas revisar.

Comprueba el resultado real

No basta con que el proyecto compile. Ejecuta las pruebas automáticas y revisa capturas en los tamaños, estados e instantes acordados.

Justifica cada elemento complejo

Usa 3D, vídeo o interacciones avanzadas solo si ayudan a entender el producto. Prepara siempre una alternativa accesible, ligera y sin movimiento.

Separa generación y publicación

Genera la versión que se va a publicar, revisa su contenido y despliega solo con autorización expresa. No publiques directamente desde la carpeta de trabajo.

Deja el proyecto listo para continuar

Documenta las decisiones, conserva comandos reproducibles y mantén desactivado lo incompleto. Cada ronda debe terminar sin errores ni cambios ocultos.
